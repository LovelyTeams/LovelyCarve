# 使用指南

本文按一次完整的分析流程介绍 LovelyCarve 桌面端。获取程序与从源码构建见根目录 [README](../README.md)，命令行用法见 [CLI 手册](CLI.md)。

## 运行环境

- Windows 10 / 11 x64，需要 WebView2 运行时（系统通常已内置）。
- 读取物理磁盘需要以管理员身份运行。
- 只读挂载需要安装 [Dokany](https://github.com/dokan-dev/dokany) 驱动。
- 二维码识别与 OCR 只在 `*-full` 构建中可用；默认构建中对应按钮会提示功能未启用。

语言（简体中文 / English）、主题（浅色 / 深色 / 樱花）、界面动画（跟随系统 / 开启 / 关闭）与挂载偏好在「设置中心 → 界面」中调整。「日志」显示当前会话的输出，可搜索、按级别筛选、复制或清空；软件版本与构建时间在「关于」中查看。

「设置中心 → 关于」提供「检查更新」和「自动检查更新」。自动检查默认关闭，不主动联网；手动检查或开启后读取 `LovelyTeams/LovelyCarve` 的公开 GitHub tags，开启时立即检查，以后每次启动检查一次。按语义化版本比较 `v1.2.0` / `1.2.0` 形式的标签，正式版忽略预发布标签；发现新版时显示提示，可复制对应标签链接到浏览器查看，不自动下载或安装。请求超时、网络错误或 GitHub 限流时可稍后手动重试。

语言切换立即生效，自动保存并同步到独立预览窗口，重启后沿用。英文界面的切换入口为 **Settings → Appearance → Language**。文件名、路径、案件名、检材内容、插件原始输出和后端原始诊断保留原文；语言设置不修改检材或案件数据。文件类型列的筛选同时接受中英文类型名。

## 案件与检材

### 案件

一个案件就是一个目录。在起始页或标题栏的「案件管理」中新建案件时选择一个空目录，目录名即案件名；「打开案件」选择已有的案件目录。起始页列出最近打开的 8 个案件，点击即可恢复；「清空」只移除本机的历史记录，不删除案件。

案件目录中：

- `case.db` 是案件台账，记录案件信息、检材登记、任务、标签和带哈希链的操作审计；
- `evidence/<检材 ID>/` 保存每份检材的卷快照、文件索引、哈希、分析结果、时间线与搜索记录。

案件只登记检材路径，不复制原件；移动案件或检材后请检查路径和加载结果。案件可以在「案件管理」中锁定，锁定后不能添加、移除检材或重建快照。早期开发版的 `.carve` 案件无法打开，需要新建案件。

原始镜像暂时不可用时，案件仍可以用已验证的索引浏览目录、筛选文件和查看属性（离线索引）；预览正文、导出、哈希等需要读取字节的操作会明确失败。恢复原路径后重新打开检材即可恢复全部功能。

### 添加检材

「添加检材」提供五种来源，也可以把文件直接拖进窗口：

| 来源 | 说明 |
| --- | --- |
| 镜像文件 | RAW / E01 / VMDK / VHD(X) / QCOW / QCOW2 / VDI / Parallels / ISO / DMG / AD1 / PMFX / LDBK 等磁盘镜像，光盘 BIN / CUE，小米 HDR1 固件与 UBI 镜像，Android `.ab` 与小米 `.bak` 备份，TAR / TAR.GZ / ZIP / 7z 归档，以及 `.hc` / `.tc` / `.luks` 加密容器。分段镜像选第一段，其余分段放在同一目录；RAW 支持 `.001` / `.000` / `.raw.001` 等数字分段和 `aa` / `aaa` 分段，缺少中间段会报错，完整性边界见 [SMRAW](formats/SMRAW.md) |
| 文件夹 | 本机目录、已解包的数据集，或 iTunes / Finder 的 iOS 本地备份（选择同时包含 `Manifest.plist` 与 `Manifest.db` 的那一层目录，详见 [iOS 备份](IOS_BACKUPS.md)）。目录中的小米 `.bak` 备份会自动展开 |
| BCP 文件 | 网安数据交换 BCP，见下文 [BCP 数据](#bcp-数据) |
| RAID 磁盘 | 逐块加入成员盘，自动检测阵列，确认后打开重组的镜像 |
| 物理磁盘 | 直接读取本机块设备，Windows 下通常需要管理员权限 |

检材加入案件后，后台会自动识别平台与检材类型，并为每个可浏览的卷建立快照和文件索引。进度、结论与失败原因在右上角「任务中心」查看；卸载检材会取消它尚未完成的任务。

光盘 `.iso`、Mode 1 / XA Form 1 的 2352 字节 `.bin` 和 `.cue` 可作为镜像文件添加。多轨或多个数据文件应选择 `.cue`，按轨道浏览其中的 ISO 9660 / Joliet 文件；CUE 中的音频轨保留原始范围。整镜像哈希和源导出使用完整数据文件按 FILE 顺序拼接的原始字节，不含 CUE 文本，也不补入未存储的间隙。支持边界见 [光盘镜像](formats/CDFS.md)。

小米 `HDR1` `.bin` 固件和独立 UBI 镜像可作为镜像文件添加。展开 UBI 分区后，`<卷名>.img` 是重组后的原始逻辑卷，SquashFS 卷另有同名目录供浏览、预览和导出。原始固件字节保持不变；UBIFS 当前只提供原始逻辑卷，详见 [UBI 固件](formats/UBI.md)。

ZIP 或文件夹检材中的小米 `.bak` 备份会自动显示为同名目录，展开后可浏览 `apps/<包名>/…` 下的数据库、偏好设置和其他应用文件，并使用现有预览与导出功能。程序只在临时目录物化备份的 TAR 内容，卸载检材后自动清理，不修改原始检材。

案件中的 ZIP 首次加载时完整解码全部备份，展开清单保存在案件里；之后再打开案件会直接恢复备份目录，打开某个备份内的文件时才解码该备份，首次读取会稍有等待。普通 `.bak`、损坏或需要密码的备份保留为原始文件；详细边界见 [小米备份](formats/MIUI_BAK.md)。

也可直接选择 Android `.ab` 或小米 `.bak` 作为镜像文件打开，未压缩及压缩备份会显示应用文件树；ZIP / 文件夹内的 `.ab` 同样自动展开。当前不支持备份密码解锁，独立打开加密备份会明确报错，详见 [Android 备份](formats/ANDROID_BACKUP.md)。

不完整 RAW 可以通过 CLI `images open <镜像路径> --raw-read-mode force` 或 IPC `rawReadMode: "force"` 显式强行读取连续分片前缀；桌面文件选择器保持默认严格检查。强行读取的补零字节保留坏区审计，模式只在当前会话有效，完整性边界见 [SMRAW](formats/SMRAW.md#不完整-raw-的强行读取)。

QCOW 支持 v1/v2/v3、DEFLATE 压缩和 RAW/QCOW 差分父链；相对父路径按子镜像所在目录解析，缺少父文件会报错。legacy AES 镜像可通过 CLI / IPC 提供密码或原始密钥，桌面文件选择器尚无专用密码弹窗。完整能力和边界见 [QCOW](formats/QCOW.md)。

Parallels 镜像请选择 `DiskDescriptor.xml` 或 `.hdd` 目录，保留数据文件在原目录内；支持 v2 固定、稀疏、分段及差分父链。独立 `.hds` 仅适用于没有父链的基础盘；有描述符时会提示选择描述符。扩展 HDS / v1 / Parallels 加密明确报错，范围与验证见 [PHDI](formats/PHDI.md)。

## 镜像信息

![镜像信息页](images/image-info.png)

镜像信息页是一页概览，从上到下依次为：

1. **检材头部**：文件名与格式（会话镜像显示「解密视图」或「VSS 卷影副本」）、可复制的完整路径、逻辑大小（压缩或稀疏格式另显示实际占用）。右侧是平台识别结论（平台 · 厂商 · 检材类型）、重新识别和「导出源镜像」。备份只显示一次“备份”，完整识别描述保留在标签的悬停提示中。
2. **卷与分区**：分区表类型、磁盘布局图（斜纹表示未分配空间，点击色块定位到对应分区）和分区列表。悬停起始扇区可查看结束扇区、扇区数和字节偏移。操作列按分区提供：
   - 可挂载文件系统的「挂载」与共享；
   - BitLocker 的锁定状态、解锁和导出解密镜像；
   - LUKS 与 FileVault 2 分区的「解锁」，卡片右上角的「解锁加密容器」也可解锁 LUKS / VeraCrypt / FileVault 2；
   - 卷影副本：有副本时显示「卷影副本 N」，展开后列出创建时间（UTC）、属性和计算机名，可打开为只读镜像在新标签页中浏览；有 VSS 区而无副本时显示「无卷影副本」。

   归档、AD1、Docker 等逻辑检材没有分区表，这里只有一个合成根。
3. **RAID 检测**：块设备检材参与 LVM / mdadm 阵列，或疑似无分区表的阵列成员时出现。ZIP / TAR / 7z、文件夹、AD1、Docker 与 Android / iOS 逻辑备份不显示此卡片，也不从该页面触发 RAID 检测。
   - 识别 mdadm 元数据 0.90 / 1.0 / 1.1 / 1.2 的 linear 与 RAID0/1/4/5/6/10，Intel RST / VROC（IMSM）与 Dell PERC、LSI MegaRAID、Adaptec 等控制器（SNIA DDF）的固件 RAID 卷，以及无元数据成员盘的 RAID0 / RAID5 推定。超级块在盘尾的成员（0.90 / 1.0、IMSM、DDF）看起来是普通磁盘，首次打开它的信息页时也会重新检测。
   - IMSM 只用硬盘序列号标识成员盘：E01 记录了序列号，或镜像大小只与一块成员盘相同时，成员按元数据排序；否则 RAID1 仍可直接重组，其他级别的成员显示「未匹配」、阵列显示「成员顺序未知」，按检测说明给出的几何用「手动重组」完成。
   - 成员按槽位列出，并标注陈旧、重建中、备用、故障或重复加载；这些成员不被读取。md 已记为故障而移除的成员不影响重组，阵列自动「已降级重组」；元数据仍登记、但没有加载或已陈旧的成员，卡片显示「缺 N 块，可降级重组」，加载其余成员盘后自动重组，确认无法获得时点「降级重组」。
   - md 阵列上的 LVM 卷组随阵列显示；跨多个物理卷的逻辑卷（如 NAS 由多组阵列拼成的存储空间）在卷组行提供「打开逻辑卷」。
   - 「手动重组」按列序选择成员盘，指定级别、校验或副本布局、块大小和数据偏移；没有镜像的成员用「缺盘列」占位，也可把某列标为不读取，按校验或镜像重建。格式能力与限制见 [Linux md RAID](formats/MDRAID.md) 与 [固件 RAID](formats/FIRMWARE_RAID.md)。
4. **完整性校验**：勾选 MD5 / SHA1 / SHA256 / SM3 计算整盘哈希，可随时终止。E01 带有采集时记录的 MD5 / SHA1 时逐项标出一致、不一致或未校验；读到坏区时提示结果包含合成的零字节。
5. **详细信息**：精确字节数、扇区大小、磁盘标识（GPT 磁盘 GUID 或 MBR 签名）；E01 的采集记录（案件编号、证据编号、检验人、采集时间、设备型号、序列号等）；卷影副本会话另列来源分区、快照时间与副本 ID。

解锁时在弹窗中输入凭据，解锁在「任务中心」后台进行，成功后源镜像的对应分区即可浏览，不会新开标签页。BitLocker 支持密码、48 位恢复密钥、BEK 启动密钥、明文密钥、FVEK 与 VMK；LUKS 支持密码与已恢复的主密钥；VeraCrypt 支持普通卷、隐藏卷和 PIM；FileVault 2（CoreStorage）先列出逻辑卷，再用密码、个人恢复密钥或已恢复的 VMK 解锁，APFS 原生加密不在此列。凭据不写入案件，重启程序后需要重新解锁。各格式的细节见 [格式与读取器](formats/README.md)。

## 文件浏览与预览

![文件列表与预览](images/file-browser.png)

「文件列表」顶部是地址栏，左侧是目录树，中间是文件表，右侧是预览栏。

- **浏览**：双击目录进入，地址栏中的路径可点击跳转，点击当前目录名复制完整路径；路径很深时先省略中间各级，当前目录始终可见。点击表头排序。
- **范围与筛选**：表格上方筛选条的「当前目录 / 所有子目录」切换列表范围，「所有子目录」以当前目录为根递归列出全部文件，名称后淡显所在子目录；在搜索框输入关键字会在所有子目录中按文件名或路径查找。「文件类型」按文件类别多选过滤，目录加载完整时显示各类数量。指针移到表头时出现漏斗，可按名称、类型、大小和时间等列筛选；大小与时间范围须填入有效值，范围颠倒时会提示错误并保留原结果。每个生效的条件（包括「隐藏空目录」）都在筛选条上显示为标签，点击标签修改，点 × 移除，「清除全部」一次清空。筛选后没有结果时，列表注明条目被筛掉，而不是空目录。
- **导出与统计**：筛选条右侧的「导出」作用于勾选的文件和文件夹，未勾选时作用于选中的行。页脚显示条目数（按条件查询时为「符合条件」的条目数）、勾选数量与大小，以及卷快照状态。
- **取证状态**：删除项以红字、删除线和「已删除」标签显示；未分配空间、NTFS 命名数据流（ADS）、ReFS 快照流、符号链接和文件系统元数据节点依卷类型显示。删除项可以浏览，不代表内容仍然完整。
- **右键菜单**：查看详情、回到原始目录、挂载、导出文件 / 文件夹、计算哈希、识别文件类型、插件分析任务、复制名称 / 完整路径 / 取证信息，以及打标签。勾选多项后可以批量操作。
- **预览**：单击文件打开右侧预览，分为「详细信息」「原类型」「文本」「十六进制」。原类型视图支持图片、音视频、PDF 与 Office 文档、归档成员树、CSV、SQLite（自动回放 `-wal`，并提供「已删除记录」）、Realm，以及 PE / ELF / Mach-O / GGUF 等结构化视图；「识别真实类型」用 Magika 按内容判断类型，完整构建另有「扫描二维码」和「识别文字」。LevelDB 与 MMKV 目前只能用文本或十六进制查看。
- **独立窗口**：拖动预览标题栏或点击拆分按钮，可以把预览拆成独立窗口，之后选中的文件都在该窗口显示，也可以随时停靠回主窗口。窄窗口中预览浮在表格上方，关闭后继续浏览完整列表。

文件属性中的「加密类型：未检测」只表示没有检测依据，不能据此认定文件未加密。

## 校验与导出

- 镜像信息页计算整盘哈希；文件列表右键可计算一个或多个文件的哈希。
- 文件可以单独或批量导出；文件夹导出时选择保留原始目录结构或打包为 ZIP。
- 镜像头部的「导出源镜像」写出整盘 RAW，已解锁的 LUKS / VeraCrypt / BitLocker 分区以明文写出，整盘布局与大小保持不变；BitLocker 分区行的导出也生成整盘镜像，目标分区为解密后的字节。同一镜像导出期间不能重复启动；完成、失败或后端确认取消后可以再次导出，发出取消请求后需等待任务结束。导出进度、目标路径和完成／失败／取消结果会保留在当前检材的「任务中心」，也可以在那里取消正在进行的导出。
- 导出的文件名会适配主机文件系统（非法字符、Windows 设备名等），且从不覆盖已有文件；原始路径与来源以案件记录为准。
- 整盘读取必须覆盖完整的逻辑长度。容错读取遇到源坏区时以零补齐并记录坏区，任务结果中的 `bad_regions`、`synthetic_bytes` 和 `read_faults_detected` 说明结果是否包含合成字节，应与导出结果一并保存。

## 全局搜索

在「工具 → 全局搜索」中点击「新建搜索」：

- 每行一个关键词，或在高级选项中填写正则表达式；
- 搜索范围默认全部分区，也可以按分区、标签或目录限定；
- 高级选项可选择编码（ASCII、UTF-8、UTF-16LE、UTF-16BE、GBK）、是否包含已删除文件与未分配空间、是否区分大小写、是否计算命中文件的哈希，以及单文件与全局命中上限（须为正整数）。

搜索在后台运行，结果陆续出现。结果可以在结果中筛选、按文件或哈希去重、导出 CSV；单击查看完整上下文、匹配方式、偏移和编码，双击或点击「定位」跳到文件列表并高亮命中字节。读取失败的对象单独计数，不会被当作没有命中。搜索历史保存在案件中。

## 时间线

在「工具 → 时间线」中点击「创建时间线」，把文件修改时间、插件事件和 NTFS USN 日志投影为事件；源数据变化后页面会提示更新。

- **活动热力图**按年显示每日事件数，点击某一天筛选明细；**事件趋势**可从年逐级下钻到秒。键盘操作：热力图中上下键移动一天、左右键移动一周，Home / End 跳到首末项，Enter / 空格选择。
- 顶部可以搜索内容、按事件类型筛选、包含已删除文件；结果可导出 CSV，文件事件可「定位」回文件列表。
- 文件事件目前只投影修改时间；没有时区信息的本地时间（如 FAT）不参与投影。

## 文件恢复

在「工具 → 文件恢复」中点击「新建扫描」，选择恢复方式（可同时选择）：

- **文件系统恢复**：读取 FAT12/16/32、NTFS、exFAT 的删除记录，并在扫描范围内按引导扇区和残留 `$MFT` 查找丢失分区，保留原文件名和目录结构。可取消不需要的文件系统；「同时列出已知分区的现存文件」默认关闭，此时已知分区只列删除项，丢失分区仍列出能够重建的全部文件。
- **签名雕刻**：选择文件类型（图像、文档、归档、音频、数据库共 14 种），在 512 字节块边界检查签名，再解析文件结构计算长度，用于查找没有目录记录的文件。高级选项可以设置单文件大小上限与结果数量上限。

扫描范围可选整个镜像、指定分区、分区间隙或扇区范围（起始扇区与扇区数量，数量留空扫描至镜像末尾；扇区大小使用镜像报告的值），查找丢失分区时可选分区间隙。两种方式都选时先扫描文件系统、再雕刻签名；运行中可以暂停、继续或取消。左侧「扫描记录」列出当前检材最近的扫描，记录只保存在当前进程中，重启或卸载检材后不保留。

结果按文件列表的方式浏览：左侧目录树，右侧地址栏和文件表。根目录列出恢复出的卷（标注丢失分区、MFT 重建或已知分区）和「签名雕刻」，双击文件夹或点击名称进入，用面包屑或「返回上一级」导航；删除的文件和目录以红色划线标出。雕刻结果按格式归入「签名雕刻」下的文件夹，不冒充原目录，表格改为显示起始偏移和置信度。顶部筛选框与类别筛选当前文件夹及其子目录中的文件，可按名称、路径、类型或偏移匹配。单击文件在右侧查看详情：文件系统记录显示原路径、时间、所在卷和节点标识，雕刻结果显示偏移、置信度和图像预览。

NTFS 引导区被覆盖后，若 `$MFT` 自身的分配信息、物理位置和相邻系统记录能够互相验证，会显示「MFT 重建」卷。推导的几何只用于初始化只读读取器，不写回镜像；原卷末尾未知时将读取限制在现有来源范围内。完整 `$MFT` 属性表不连续、稀疏或无法唯一确认几何时不猜测。回收站中对应的 `$I` / `$R` 记录在名称、父目录和长度匹配后可还原原文件名及路径，来源节点和回收站路径仍随结果和报告保留；无法确认的同名目录使用独立身份，不合并。

勾选文件或文件夹后点击「恢复所选」，勾选文件夹会选择其下可读的文件；未勾选时「恢复全部」作用于本次扫描的全部可读文件和雕刻结果。雕刻结果直接写入目标目录，同时生成 SHA-256 与 DFXML 报告。文件系统记录写入目标目录中新建的 `recovery-<UUID>` 子目录，并保持浏览时的目录结构：每个卷一个文件夹（`v<卷号>-<卷标>`，无卷标时用文件系统名），其下按原目录逐级还原；同名的现存与已删除目录仍分开存放，同一文件夹中重名（不区分大小写）的文件或目录依次加 `-1`、`-2` 后缀，非法字符与设备名按文件列表导出的规则替换。原路径、来源节点、输出路径、SHA-256 和读取故障保存在 `recovery-report.jsonl` 中。已有宿主文件不会被覆盖，单文件失败或取消会删除该文件的未完成输出及因此留空的文件夹，已完成文件保留。

可读映射表示能够尝试读取，不保证内容未被覆盖。FAT/exFAT 删除的碎片文件、丢失的记录和不支持的加密布局仍可能无法恢复；雕刻受块对齐、碎片化和格式覆盖范围限制，签名较弱的格式可能产生误报，不能把未命中解释为文件不存在，恢复后应核验。文件系统恢复最多保留 128 个卷、20000 个文件和 20000 个目录，每卷最多遍历 200000 个节点和 64 层目录；达到限制或读取目录失败会明确提示。

## 插件分析

分析插件有三种：**系统级**在检材上识别出的某个操作系统上运行，系统的各个卷按 `/etc/fstab` 或盘符挂在一棵目录树里（例如独立的 `/home` 分区）；**检材级**分析检材的全部卷；**文件级**分析选中的文件。右上角的「任务中心」跟随当前检材标签，包含「任务」和「快速分析」两页。

- **快速分析**：顶部选择要分析的系统（检材上识别出多个系统时可切换，选择按检材记住），下方按分类列出适用于该系统的系统级插件与全部检材级插件。勾选后点击「开始分析」，每个插件以默认选项运行它的全部分析；插件格子上的图标表示它在该目标上最近一次任务的状态。已有结果的插件重新分析成功后，新结果替换旧结果。文件级分析从文件列表右键「插件分析任务…」提交，分析器声明了选项（如子项）时先填写。
- **任务**：按「进行中」「需要处理」「已结束」分组显示插件任务与内置任务（打开检材、自动识别平台、文件系统加载与索引、镜像哈希、镜像与目录导出、加密卷解锁、全局搜索、时间线、文件恢复与恢复文件导出、Docker 分析），可以取消、重新分析或跳转到结果；展开可查看对象（目标路径、关键词、分区等）、分析的系统、选项与结果计数。插件任务不能暂停，取消即结束，重新分析从头开始；旧版本暂停的任务可以开始或取消。文件恢复扫描可暂停与继续。收起面板或切换页面不影响后台任务；全局搜索与时间线构建在重新打开案件后仍会列出，其他内置任务的记录保留到关闭程序或切换案件。
- **分析结果**：侧栏「分析」按结果分类分节，每次运行以分析器名称和目标（系统或文件）为标题，下面列出记录类型及记录数；同一分析器在不同系统上的运行分别列出，告警数标在标题右侧，没有记录的类型显示为浅色。点击运行标题打开「运行信息」：关键数字（记录数、记录类型、输入文件、告警、耗时）、各记录类型的产出（点击打开该类型）、告警与输入文件、运行参数与技术信息，读不出而以零填充的源字节在页首提示。记录可按属性视图或表格视图阅读：表格的列与类型来自插件声明，点击列头排序，支持搜索与 CSV 导出（导出原始值），时间戳连同时区显示（如 `2024-01-02 03:04:05 UTC`），未记录时区的时间不标时区。点击记录在右侧查看全部字段与来源，可逐条切换上一条 / 下一条，表格中也可用方向键移动；「定位源文件」跳到检材中的来源文件。旧版本留下的结果标注「旧版」，只读显示。
- **插件管理**：「设置 → 插件」列出内置与已安装的插件包、分析器、记录类型与加载失败的包；「安装插件包…」选择 `.lcpkg` 安装或更新，已安装的插件包可以卸载（已发布的结果保留）。
- **插件日志**：插件写出的日志按插件保存在软件 exe 目录下的 `logs/plugins/<插件 id>.log`（例如 `D:\LovelyCarve\logs\plugins\`），单文件超过 8 MiB 轮转为 `.log.1` 并保留一代；写入在后台线程完成，退出时排空队列。目录不可写时记录警告，不回退到 AppData；单条消息超过 64 KiB 时截断并标记。每行形如 `2026-01-02T03:04:05.678Z INFO 消息`，无前缀的加载器诊断记为 `HOST`。「设置中心 → 界面 → 日志」显示的是界面自身的会话输出，不含插件日志。

插件是原生动态库，已发现的插件被视为可信代码，每个插件实例在独立的宿主进程中运行；安装第三方插件前请确认来源。安装包内置 [Linux 基本信息插件](LINUXINFO.md)，开发插件见 [插件协议](PLUGIN_PROTOCOL.md)。

## BCP 数据

「添加检材 → BCP 文件」可以选择一个或多个 `.bcp` 文件，程序把它们所在的目录登记为逻辑检材并打开 BCP 数据页；也可以直接添加包含 BCP 的文件夹，或把 `.bcp` 文件拖进窗口。

- 目录中有 `GAB_ZIP_INDEX.xml` 时，从索引读取数据集代码、中文列名、编码、文件名和记录数，重复出现的同一文件只计一次；正文按索引声明的列顺序解析，每条记录以换行结束、字段以制表符分隔，不含表头。没有索引时使用通用列名并扫描文件计算行数。
- 侧栏「BCP 数据」按设备与通信、即时通信、社交动态、浏览器记录、交易与支付等类别显示记录数。选择数据集后表格每次读取最多 100 条，可以翻页并在当前页内筛选；点击一行查看完整字段与来源文件。
- 分页通过文件字节偏移继续读取，不在界面中一次载入全部记录；当前页筛选只作用于已读取的 100 条，不是全量检索。索引之外的附件可以在该检材的「文件列表」中浏览。页面只读，不修改 BCP 原件或附件。

## 只读挂载

Windows 下安装 Dokany 后，可以在镜像信息页的分区行或文件列表的右键菜单中，把支持的卷（包括 Docker 容器的合并视图）只读挂载为盘符或文件夹，并可共享。卸载检材或退出程序时挂载会自动清理。
