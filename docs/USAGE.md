# 使用指南

本文按一次完整的分析流程介绍 LovelyCarve 桌面应用。获取程序与从源码构建见根目录 [README](../README.md)，命令行用法见 [CLI 手册](CLI.md)。

## 运行环境

- Windows 10 / 11 x64。
- 程序默认以普通用户权限启动，浏览镜像和文件夹无需管理员权限；读取物理磁盘或采集实时内存时，请手动以管理员身份运行。
- 只读挂载需要安装 [Dokany](https://github.com/dokan-dev/dokany) 驱动。
- 原类型视图的文档、图片与归档等格式需要另行安装 Oracle Outside In Viewer 8.5.7 运行库，安装位置的配置见 [开发指南](DEVELOPMENT.md)。
- 二维码识别与 OCR 只在命令行的 `*-full` 构建中提供。

主题（跟随系统 / 浅色 / 深色）、界面大小与首页动画在「设置中心 → 界面」中调整，更改自动保存；「插件」管理插件包，「关于」显示版本、数据目录与许可。界面文字为简体中文；文件名、路径、案件名、检材内容、插件原始输出和后端原始诊断保留原文。

## 案件与检材

### 案件

一个案件就是一个目录。在起始页或标题栏的「案件管理」中新建案件时选择一个空目录，目录名即案件名；「打开案件」选择已有的案件目录。起始页列出最近打开的案件，点击即可恢复。

案件目录中：

- `case.db` 是案件台账，记录案件信息、检材登记、任务、标签和带哈希链的操作审计；
- `evidence/<检材 ID>/` 保存每份检材的卷快照、文件索引、哈希、分析结果、时间线与搜索记录。

案件只登记检材路径，不复制原件；移动案件或检材后请检查路径和加载结果。案件可以在「案件管理」中锁定，锁定后不能添加、移除检材或重建快照。早期开发版的 `.carve` 案件无法打开，需要新建案件。

原始镜像暂时不可用时，案件仍可以用已验证的索引浏览目录、筛选文件和查看属性（离线索引）；预览正文、导出、哈希等需要读取字节的操作会明确失败。恢复原路径后重新打开检材即可恢复全部功能。

### 添加检材

「添加检材」（Ctrl+O）提供五种来源，也可以把文件直接拖进窗口：

| 来源 | 说明 |
| --- | --- |
| 镜像文件 | RAW / E01 / VMDK / VHD(X) / QCOW / QCOW2 / VDI / Parallels / ISO / DMG / AD1 / PMFX / LDBK 等磁盘镜像，光盘 BIN / CUE，小米 HDR1 固件与 UBI 镜像，Android `.ab` 与小米 `.bak` 备份，TAR / TAR.GZ / ZIP / 7z 归档，以及 `.hc` / `.tc` / `.luks` 加密容器。分段镜像选第一段，其余分段放在同一目录；RAW 支持 `.001` / `.000` / `.raw.001` 等数字分段和 `aa` / `aaa` 分段，缺少中间段会报错，完整性边界见 [SMRAW](formats/SMRAW.md) |
| 文件夹 | 本机目录、已解包的数据集，或 iTunes / Finder 的 iOS 本地备份（选择同时包含 `Manifest.plist` 与 `Manifest.db` 的那一层目录，详见 [iOS 备份](IOS_BACKUPS.md)）。目录中的小米 `.bak` 备份会自动展开 |
| BCP 文件 | 网安数据交换 BCP，见下文 [BCP 数据](#bcp-数据) |
| RAID 磁盘 | 逐块放入成员盘，载入后在镜像信息中查看检测结果，并打开重组的镜像 |
| 物理磁盘 | 直接读取本机块设备，Windows 下通常需要管理员权限 |

检材加入案件后，后台会自动识别平台与检材类型，并为每个可浏览的卷建立快照和文件索引。进度、结论与失败原因在右上角「任务中心」查看；卸载检材会取消它尚未完成的任务。

光盘 `.iso`、Mode 1 / XA Form 1 的 2352 字节 `.bin` 和 `.cue` 可作为镜像文件添加。多轨或多个数据文件应选择 `.cue`，按轨道浏览其中的 ISO 9660 / Joliet 文件；CUE 中的音频轨保留原始范围。整镜像哈希和源导出使用完整数据文件按 FILE 顺序拼接的原始字节，不含 CUE 文本，也不补入未存储的间隙。支持边界见 [光盘镜像](formats/CDFS.md)。cooked UDF 镜像或磁盘分区可直接添加，支持 1.02–2.01 的单物理分区布局；ISO/UDF bridge 优先浏览 UDF 树，范围和高级布局限制见 [UDF](formats/UDF.md)。

小米 `HDR1` `.bin` 固件和独立 UBI 镜像可作为镜像文件添加。展开 UBI 分区后，`<卷名>.img` 是重组后的原始逻辑卷，SquashFS / UBIFS 卷另有同名目录供浏览、预览和导出。原始固件字节保持不变，详见 [UBI 固件](formats/UBI.md)。

SquashFS 支持 1.0、2.0/2.1、3.0 和 4.0，包括裸镜像、固件与 UBI 卷中的文件树；旧版本的未记录时间保持未知。版本、编码及限制见 [SquashFS](formats/SQUASHFS.md)。

Netgear Sercomm NAND `factory.img` 可直接打开，解压并校验后浏览 UBI 内的原生文件系统；源哈希、十六进制视图和 RAW 导出仍保留原始压缩封装。布局与限制见 [固件](formats/FIRMWARE.md)。

JFFS2 新格式镜像支持大小端、版本化目录 / 文件片段、硬链接与空洞，可直接打开或浏览固件分段中的文件；CRC 与不支持的编码明确报错，范围见 [JFFS2](formats/JFFS2.md)。

YAFFS2 NAND 镜像可自动识别已支持的 page / spare 几何并浏览文件，支持硬链接、稀疏和范围读取。源哈希与 RAW 导出包含原始 OOB；特殊节点只显示元数据。几何、ECC 和版本重建限制见 [YAFFS2](formats/YAFFS2.md)。

YAFFS1 的 512 / 16 旧式分散 tags 镜像使用独立类型识别，支持大小端、页正文 ECC、文件与链接读取。文件长度默认遵从对象头，配置差异与限制见 [YAFFS1](formats/YAFFS1.md)。

UBIFS 可作为裸镜像或 UBI 命名卷浏览，也可位于受支持的固件分段中；原始字节视图和源哈希保持容器内容。当前支持干净的已提交树，遇到需日志重放、加密或认证的卷明确报错。范围与验证见 [UBIFS](formats/UBIFS.md)。

Buffalo `.enc` / `.trx`、TP-Link SafeLoader `.bin`、U-Boot legacy uImage 组合镜像及
Netgear `.chk` 也可直接添加。程序校验外层结构后，展示其中支持的文件系统；裸
`.cramfs` / `.romfs` 无需预先解包。支持边界见[固件](formats/FIRMWARE.md)和
[CramFS / Linux ROMFS](formats/ROM_IMAGES.md)。

通过「添加检材 → 镜像文件」添加裸 `.f2fs`、`.erofs` 或 `.img`，也可浏览分区内的这两种文件系统。
沿用文件树、预览、哈希、导出和索引操作。F2FS 使用最后有效 checkpoint；加密 / 压缩文件的内容
尚不支持。EROFS 支持未压缩与四种压缩，fragments / ztailpacking 等布局明确报错。Android sparse
包装需先展开。完整边界见 [F2FS](formats/F2FS.md) 和 [EROFS](formats/EROFS.md)。

Minix V1 / V2 / V3 镜像与磁盘分区可直接添加，沿用浏览、预览、哈希、导出和目录索引；它与固件 MINIFS 是不同格式，支持方言和验证边界见 [Minix FS](formats/MINIX.md)。

QNX4 / QNX6 Power-Safe 镜像和磁盘分区可直接浏览，QNX6 还支持已验证范围内的 MMI 布局；用法、版本与加密限制见 [QNX 文件系统](formats/QNX.md)。QNX IFS、ETFS 与 EFS 属于其他格式，本次接入不包含它们。

ZIP 或文件夹检材中的小米 `.bak` 备份会自动显示为同名目录，展开后可浏览 `apps/<包名>/…` 下的数据库、偏好设置和其他应用文件，并使用现有预览与导出功能。程序只在临时目录物化备份的 TAR 内容，卸载检材后自动清理，不修改原始检材。

案件中的 ZIP 首次加载时完整解码全部备份，展开清单保存在案件里；之后再打开案件会直接恢复备份目录，打开某个备份内的文件时才解码该备份，首次读取会稍有等待。普通 `.bak`、损坏或需要密码的备份保留为原始文件；详细边界见 [小米备份](formats/MIUI_BAK.md)。

也可直接选择 Android `.ab` 或小米 `.bak` 作为镜像文件打开，未压缩及压缩备份会显示应用文件树；ZIP / 文件夹内的 `.ab` 同样自动展开。当前不支持备份密码解锁，独立打开加密备份会明确报错，详见 [Android 备份](formats/ANDROID_BACKUP.md)。

不完整 RAW 可以通过 CLI `images open <镜像路径> --raw-read-mode force`（命令参数 `rawReadMode: "force"`）显式强行读取连续分片前缀；桌面应用添加检材时保持默认严格检查。强行读取的补零字节保留坏区审计，模式只在当前会话有效，完整性边界见 [SMRAW](formats/SMRAW.md#不完整-raw-的强行读取)。

QCOW 支持 v1/v2/v3、DEFLATE 压缩和 RAW/QCOW 差分父链；相对父路径按子镜像所在目录解析，缺少父文件会报错。legacy AES 镜像可通过 CLI 提供密码或原始密钥，桌面应用尚无专用密码弹窗。完整能力和边界见 [QCOW](formats/QCOW.md)。

Parallels 镜像请选择 `DiskDescriptor.xml` 或 `.hdd` 目录，保留数据文件在原目录内；支持 v2 固定、稀疏、分段及差分父链。独立 `.hds` 仅适用于没有父链的基础盘；有描述符时会提示选择描述符。扩展 HDS / v1 / Parallels 加密明确报错，范围与验证见 [PHDI](formats/PHDI.md)。

## 镜像信息

镜像信息页是一页概览，从上到下依次为：

1. **检材头部**：文件名与格式、完整路径与逻辑大小。右侧是平台识别结论（平台、厂商与检材类型）、平台选择、「导出源镜像」和重新识别。自动识别有误或没有识别出平台时，可在平台选择中手动指定（检材须已加入案件）：手动指定的平台保存在案件里，重新识别不会覆盖，选「自动识别」恢复自动结论，案件锁定时不可修改。

   DJI 无人机镜像及提取的系统目录会自动识别为「无人机 DJI」；识别同时要求系统属性中的 DJI 厂商、DJI 固件版本及飞行 / 导航服务。仅有 DJI 手机应用、媒体文件或分区名称不会命中。缺少这些标志的型号暂不能据此识别；设备代号按检材原值保留，不猜测商品型号。CLI `images os detect` 返回固件版本、设备代号和已记录的 Android 基础版本，`plugins systems list` 列出 `dji` 系统。
2. **卷与分区**：分区表类型与分区列表。按分区提供：
   - 可挂载文件系统的「挂载」与共享；
   - BitLocker 的锁定状态、解锁和导出解密镜像；
   - LUKS 与 FileVault 2 分区的「解锁」，卡片右上角的「解锁加密容器」也可解锁 LUKS / VeraCrypt / FileVault 2；
   - 卷影副本：列出创建时间（UTC）、属性和计算机名，可重建为只读镜像并在新标签页中浏览。

   归档、AD1、Docker 等逻辑检材没有分区表，这里只有一个合成根。
3. **RAID 检测**：块设备检材参与 LVM / mdadm 阵列，或疑似无分区表的阵列成员时出现；检测扫描所有已加载的镜像。ZIP / TAR / 7z、文件夹、AD1、Docker 与 Android / iOS 逻辑备份不显示此卡片。
   - 识别 mdadm 元数据 0.90 / 1.0 / 1.1 / 1.2 的 linear 与 RAID0/1/4/5/6/10，Intel RST / VROC（IMSM）与 Dell PERC、LSI MegaRAID、Adaptec 等控制器（SNIA DDF）的固件 RAID 卷，以及无元数据成员盘的 RAID0 / RAID5 推定。超级块在盘尾的成员（0.90 / 1.0、IMSM、DDF）看起来是普通磁盘，首次打开它的信息页时也会重新检测。
   - IMSM 只用硬盘序列号标识成员盘：E01 记录了序列号，或镜像大小只与一块成员盘相同时，成员按元数据排序；否则 RAID1 仍可直接重组，其他级别的成员显示「未匹配」、阵列显示「成员顺序未知」，按检测说明给出的几何用「手动重组」完成。
   - 成员按槽位列出，并标注陈旧、重建中、备用、故障或重复加载；这些成员不被读取。md 已记为故障而移除的成员不影响重组，阵列自动「已降级重组」；元数据仍登记、但没有加载或已陈旧的成员，卡片显示「缺 N 块，可降级重组」，加载其余成员盘后自动重组，确认无法获得时点「降级重组」。重组后的阵列可打开为新标签页，也可导出为镜像。
   - md 阵列上的 LVM 卷组随阵列显示；跨多个物理卷的逻辑卷（如 NAS 由多组阵列拼成的存储空间）在卷组行提供「打开逻辑卷」。
   - 「手动重组」按列序选择成员盘，指定级别、校验或副本布局、块大小和数据偏移；没有镜像的成员用「缺盘列」占位，也可把某列标为不读取，按校验或镜像重建。格式能力与限制见 [Linux md RAID](formats/MDRAID.md) 与 [固件 RAID](formats/FIRMWARE_RAID.md)。
4. **完整性校验**：勾选 MD5 / SHA1 / SHA256 / SM3 计算整盘哈希，可随时终止。E01 带有采集时记录的 MD5 / SHA1 时逐项标出一致、不一致或未校验；读到坏区时提示结果包含合成的零字节。
5. **详细信息**：精确字节数、扇区大小、磁盘标识（GPT 磁盘 GUID 或 MBR 签名）；E01 的采集记录（案件编号、证据编号、检验人、采集时间、设备型号、序列号等）；卷影副本会话另列来源分区、快照时间与副本 ID。

解锁时在弹窗中输入凭据，解锁在「任务中心」后台进行，成功后源镜像的对应分区即可浏览，不会新开标签页。BitLocker 支持密码、48 位恢复密钥、BEK 启动密钥、明文密钥、FVEK 与 VMK；LUKS 支持密码与已恢复的主密钥；VeraCrypt 支持普通卷、隐藏卷和 PIM；FileVault 2（CoreStorage）先列出逻辑卷，再用密码、个人恢复密钥或已恢复的 VMK 解锁，APFS 原生加密不在此列。凭据不写入案件，重启程序后需要重新解锁。各格式的细节见 [格式与读取器](formats/README.md)。

## 文件浏览与预览

「文件列表」左侧是目录树（可收起），中间是文件表，右侧是详情面板（可收起）。

- **浏览**：单击一行选中它；双击或按 Enter 打开：目录进入，文件在详情面板中预览。工具栏提供显示目录树、上一级、刷新和详情面板开关；点击表头排序。
- **勾选**：行首复选框勾选文件或目录，表头复选框勾选全部已加载的行；筛选条显示已勾选的数量，可一次取消勾选。
- **目录树**：分区是树的根，目录首次展开时列出子目录；点击名称进入目录。缩进参考线标出层级，选中行所在的那条更亮。一个目录里只有一个子目录、没有其他条目时，两者合并为一行（如 `Windows/System32`），点击其中任一段名称进入对应目录；滚动时，首个可见行的上级目录固定在树顶部，点击可回到该目录。
- **图标**：文件按名称和扩展名显示类型图标（源码、文档、图片、音视频、压缩包、可执行文件、邮件、数据库、磁盘镜像等，扩展名不区分大小写），分区、未分配空间、ADS 等取证节点有各自的图标；图标统一用次要前景色。
- **范围与筛选**：筛选条的「当前目录 / 所有子目录」切换列表范围，「所有子目录」以当前目录为根递归列出全部文件。工具栏的筛选框按名称筛选当前范围（支持 `*` `?` 通配），生效的名称条件显示在筛选条上，可一键清除；「列设置」选择显示的列。筛选后没有结果时，列表注明没有匹配的文件，而不是空目录。列表随滚动分页读取，排序与筛选由后端执行。
- **导出、哈希与标签**：筛选条的「导出」「哈希」和标签作用于勾选的文件和文件夹。标签有「重点」「可疑」「已排除」，保存在案件中；没有打开案件时只在本次运行中有效。页脚显示条目数与已加载数量。
- **取证状态**：删除项以红字、删除线和「已删除」标签显示；未分配空间、NTFS 命名数据流（ADS）、ReFS 快照流、符号链接和文件系统元数据节点依卷类型显示。删除项可以浏览，不代表内容仍然完整。
- **右键菜单**：行菜单提供打开目录、查看详情、导出文件或目录、导出勾选项、计算哈希、复制名称或路径、打标签与清除标签；右键已勾选的行时，导出、哈希与标签作用于全部勾选项。
- **预览**：详情面板分为「详细信息」「原类型视图」「文本」「十六进制」。详细信息列出元数据、时间、数据段与文件哈希（可计算或重新计算）；文本按检测到的编码解码，并标出无法解码的字节；十六进制每行 16 字节，随滚动按块读取，可跳到指定偏移。原类型视图对源码按文件名或扩展名显示语法高亮（单次读取文件开头最多 1 MiB）；Windows x64 上其他格式由另行安装的 Outside In Viewer 在独立进程中显示。SQLite（含 `-wal` 回放与删除记录）、Realm、PE / ELF / Mach-O / GGUF、ZIP、CSV 等结构化解析、类型识别、二维码与 OCR 目前通过 [命令行](CLI.md) 使用。


文件属性中的「加密类型：未检测」只表示没有检测依据，不能据此认定文件未加密。

## 校验与导出

- 镜像信息页计算整盘哈希；文件列表可计算一个或多个文件的哈希。
- 文件可以单独或批量导出；文件夹导出时选择保留原始目录结构或打包为 ZIP。
- 镜像头部的「导出源镜像」写出整盘 RAW，已解锁的 LUKS / VeraCrypt / BitLocker 分区以明文写出，整盘布局与大小保持不变；BitLocker 分区行的导出也生成整盘镜像，目标分区为解密后的字节。同一镜像导出期间不能重复启动；完成、失败或后端确认取消后可以再次导出，发出取消请求后需等待任务结束。导出进度、目标路径和完成／失败／取消结果会保留在当前检材的「任务中心」，也可以在那里取消正在进行的导出。
- 导出的文件名会适配主机文件系统（非法字符、Windows 设备名等），且从不覆盖已有文件；原始路径与来源以案件记录为准。
- 整盘读取必须覆盖完整的逻辑长度。容错读取遇到源坏区时以零补齐并记录坏区，任务结果中的 `bad_regions`、`synthetic_bytes` 和 `read_faults_detected` 说明结果是否包含合成字节，应与导出结果一并保存。

## 全局搜索

在「工具 → 全局搜索」中点击「新建搜索」：

- 每行一个关键词，或在高级选项中填写正则表达式；
- 搜索范围默认全部分区；
- 高级选项可选择编码（ASCII、UTF-8、UTF-16LE、UTF-16BE、GBK）、是否包含已删除文件与未分配空间、是否区分大小写、是否计算命中文件的哈希，以及单文件与全局命中上限（须为正整数）。

搜索在后台运行，结果陆续出现。结果可以在结果中筛选内容、文件名或路径，按文件或哈希去重，导出 CSV；单击命中查看上下文、匹配方式、偏移和编码，「定位文件」在文件列表中显示命中所在的文件。读取失败的对象单独计数，不会被当作没有命中。搜索记录保存在案件中，可删除。

## 时间线

在「工具 → 时间线」中点击「创建时间线」，把文件修改时间、插件事件和 NTFS USN 日志投影为事件；源数据变化后页面会提示更新。

- **事件趋势**按年、月或日显示事件数；顶部可以搜索事件内容或文件路径、包含已删除文件。
- 事件列表分页读取，可导出 CSV；单击事件在右侧查看内容、来源与附加信息，文件事件可「在文件列表中显示」。
- 文件事件目前只投影修改时间；没有时区信息的本地时间（如 FAT）不参与投影。

## 文件恢复

在「工具 → 文件恢复」中点击「新建扫描」，选择恢复方式（可同时选择）：

- **文件系统恢复**：读取 FAT12/16/32、NTFS、exFAT 的删除记录，并在扫描范围内按引导扇区和残留 `$MFT` 查找丢失分区，保留原文件名和目录结构。可取消不需要的文件系统；「同时列出已知分区的现存文件」默认关闭，此时已知分区只列删除项，丢失分区仍列出能够重建的全部文件。
- **签名雕刻**：选择文件类型（图像、文档、归档、音频、数据库共 14 种），在 512 字节块边界检查签名，再解析文件结构计算长度，用于查找没有目录记录的文件。高级选项可以设置单文件大小上限与结果数量上限。

扫描范围可选整个镜像、指定分区、未分配空间或自定义扇区范围（起始扇区与扇区数量，数量留空扫描至镜像末尾；扇区大小使用镜像报告的值）。两种方式都选时先扫描文件系统、再雕刻签名；运行中可以暂停、继续或取消。左侧「扫描记录」列出当前检材最近的扫描，记录只保存在本次会话中，重启或卸载检材后不保留。

结果分为「文件系统记录」与「签名雕刻」：文件系统记录按记录保存的原路径列出，标注所在卷（含丢失分区与 MFT 重建卷）和现存或已删除状态；雕刻结果没有原始路径与时间戳，列出格式与起始偏移。顶部筛选框按文件名或路径筛选。单击文件在右侧查看详情：文件系统记录显示原路径、时间、所在卷与数据映射，雕刻结果显示偏移与大小；可以单独恢复该文件。

NTFS 引导区被覆盖后，若 `$MFT` 自身的分配信息、物理位置和相邻系统记录能够互相验证，会显示「MFT 重建」卷。推导的几何只用于初始化只读读取器，不写回镜像；原卷末尾未知时将读取限制在现有来源范围内。完整 `$MFT` 属性表不连续、稀疏或无法唯一确认几何时不猜测。回收站中对应的 `$I` / `$R` 记录在名称、父目录和长度匹配后可还原原文件名及路径，来源节点和回收站路径仍随结果和报告保留；无法确认的同名目录使用独立身份，不合并。

「恢复全部」恢复本次扫描的全部雕刻结果与可读取的文件系统记录，也可以在详情中恢复单个文件。雕刻结果直接写入目标目录，同时生成 SHA-256 与 DFXML 报告。文件系统记录写入目标目录中新建的 `recovery-<UUID>` 子目录，并保持浏览时的目录结构：每个卷一个文件夹（`v<卷号>-<卷标>`，无卷标时用文件系统名），其下按原目录逐级还原；同名的现存与已删除目录仍分开存放，同一文件夹中重名（不区分大小写）的文件或目录依次加 `-1`、`-2` 后缀，非法字符与设备名按文件列表导出的规则替换。原路径、来源节点、输出路径、SHA-256 和读取故障保存在 `recovery-report.jsonl` 中。已有宿主文件不会被覆盖，单文件失败或取消会删除该文件的未完成输出及因此留空的文件夹，已完成文件保留。

可读映射表示能够尝试读取，不保证内容未被覆盖。FAT/exFAT 删除的碎片文件、丢失的记录和不支持的加密布局仍可能无法恢复；雕刻受块对齐、碎片化和格式覆盖范围限制，签名较弱的格式可能产生误报，不能把未命中解释为文件不存在，恢复后应核验。文件系统恢复最多保留 128 个卷、20000 个文件和 20000 个目录，每卷最多遍历 200000 个节点和 64 层目录；达到限制或读取目录失败会明确提示。

## 插件分析

分析插件有三种：**系统级**在检材上识别出的某个操作系统上运行，系统的各个卷按 `/etc/fstab` 或盘符挂在一棵目录树里（例如独立的 `/home` 分区）；**检材级**分析检材的全部卷；**文件级**分析选中的文件，目前通过命令行提交。标题栏的「任务中心」跟随当前检材标签页，包含「任务」和「快速分析」两页。

- **快速分析**：选择要分析的系统或整个检材，勾选插件功能后提交，每个功能以默认选项运行；提交后任务出现在「任务」页。已有结果的功能重新分析成功后，新结果替换旧结果。
- **任务**：按「进行中」与「已结束」分组显示插件任务与内置任务（打开检材、自动识别平台、文件系统加载与索引、镜像哈希、镜像与目录导出、加密卷解锁、全局搜索、时间线、文件恢复与恢复文件导出、Docker 分析），可以搜索、取消，或跳转到对应页面与分析结果。插件任务不能暂停，取消即结束；插件任务的开始、重新分析与删除通过命令行进行。文件恢复扫描可暂停与继续。收起面板或切换页面不影响后台任务；全局搜索与时间线构建在重新打开案件后仍会列出，其他内置任务的记录保留到关闭程序或切换案件。
- **分析结果**：「分析 → 分析结果」按结果分类列出每次运行（分析器名称与目标，告警数标在右侧）及其记录类型与记录数，可以搜索结果项。选中记录类型后表格分页列出记录，列与类型来自插件声明，时间戳连同时区显示，未记录时区的时间不标时区；点击记录在右侧查看全部字段与源文件，「定位」跳到检材中的来源文件。旧版本留下的结果标注「旧版」，只读显示。
- **插件管理**：「设置中心 → 插件」列出已发现的插件包、分析器与加载失败的包；「安装插件…」选择 `.lcpkg` 安装或更新，已安装的插件包可以卸载（已发布的结果保留）。
- **插件日志**：插件写出的日志按插件保存在软件 exe 目录下的 `logs/plugins/<插件 id>.log`（例如 `D:\LovelyCarve\logs\plugins\`），单文件超过 8 MiB 轮转为 `.log.1` 并保留一代；写入在后台线程完成，退出时排空队列。目录不可写时记录警告，不回退到 AppData；单条消息超过 64 KiB 时截断并标记。每行形如 `2026-01-02T03:04:05.678Z INFO 消息`，无前缀的加载器诊断记为 `HOST`。

目录与压缩包检材的插件来源路径相对于检材内部根目录，不包含文件树中的检材名称；定位后，导航栏仍保留该名称。源检材缺失但已有可用索引时，仍可定位并浏览来源目录；预览文件内容需要恢复源检材。

插件是原生动态库，已发现的插件被视为可信代码，每个插件实例在独立的宿主进程中运行；安装第三方插件前请确认来源。安装包内置 [Linux 基本信息插件](LINUXINFO.md)，开发插件见 [插件协议](PLUGIN_PROTOCOL.md)。

## BCP 数据

「添加检材 → BCP 文件」可以选择一个或多个 `.bcp` 文件，程序把它们所在的目录登记为逻辑检材并打开 BCP 数据页；也可以直接添加包含 BCP 的文件夹。

- 目录中有 `GAB_ZIP_INDEX.xml` 时，从索引读取数据集代码、中文列名、编码、文件名和记录数，重复出现的同一文件只计一次；正文按索引声明的列顺序解析，每条记录以换行结束、字段以制表符分隔，不含表头。没有索引时使用通用列名并扫描文件计算行数。
- 侧栏「BCP 数据」按设备与通信、即时通信、社交动态、浏览器记录、交易与支付等类别显示有记录的分类。选择数据集后表格分页读取记录，可以在已读取的记录中筛选；点击一行查看完整字段。
- 分页通过文件字节偏移继续读取，不在界面中一次载入全部记录；筛选只作用于已读取的记录，不是全量检索。索引之外的附件可以在该检材的「文件列表」中浏览。页面只读，不修改 BCP 原件或附件。

## 只读挂载

Windows 下安装 Dokany 后，可以在镜像信息页的「卷与分区」中，把支持的卷只读挂载为盘符或文件夹，并可共享；Docker 容器的合并视图可通过命令行挂载。卸载检材或退出程序时挂载会自动清理。
