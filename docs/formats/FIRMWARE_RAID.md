# 固件 RAID：Intel IMSM 与 SNIA DDF

Intel RST / VROC 写入的 IMSM 元数据，以及 Dell PERC、LSI / Broadcom MegaRAID、Adaptec 控制器和 mdadm `ddf` 容器写入的 SNIA DDF 元数据，由纯 Rust 代码识别。每个卷按元数据记录的级别、条带大小、各成员起始扇区和使用大小，用 [Linux md RAID](MDRAID.md) 的同一套读取器组装，注册为只读的合成检材（`assembled://imsm:…`、`assembled://ddf:…`），之后的浏览、哈希、导出和索引与普通磁盘相同。实现入口见文末，整体流程见 [架构说明](../ARCHITECTURE.md)。

## 能力矩阵

| 项目 | IMSM | DDF |
| --- | --- | --- |
| 元数据位置 | 锚点在磁盘倒数第二个扇区，以 `Intel Raid ISM Cfg Sig. ` 和版本号开头；超过一个扇区的元数据块（MPB）续写在锚点之前。512 与 4096 字节扇区的磁盘都可读，块计数统一换算为 512 字节扇区 | 锚点在最后一个 512 字节扇区（`0xDE11DE11`），据其找到主副本和可选的备份副本：头之后依次是物理盘记录、虚拟盘记录、配置记录和本盘数据 |
| 校验 | MPB 的 32 位校验和；大小越界或校验失败的 MPB 列入诊断，该盘不参与组装 | 锚点、主备头和读取的每个结构（物理盘记录、虚拟盘记录、每条配置记录、本盘数据）都核对 CRC-32；主备头还须与锚点的容器 GUID、版本和副本位置一致。所选副本中有结构损坏时改用另一副本 |
| 权威副本 | 同一容器（family number 相同）中 generation 最高的 MPB；同一 generation 内容不同时给出诊断 | 同一容器（头 GUID 相同）中序号最高的头（标为正在写入的头按少一次更新计）提供物理盘与虚拟盘记录；每个虚拟盘取所有已加载磁盘上序号最高的配置记录 |
| 成员与槽位 | 磁盘表只以硬盘序列号标识成员，按下文的规则匹配检材 | 每块盘在本盘数据中记录自己的引用号，配置记录列出每个位置的引用号和起始扇区，槽位直接由元数据确定 |
| 级别 | RAID0、两盘 RAID1、RAID5（左异步）、RAID10（成对镜像再条带，包括旧固件记为 RAID1 的四盘卷）；同一容器中的多个卷（Matrix RAID）分别组装 | RAID0；两盘或三盘 RAID1；RAID4（校验在首盘或末盘）；RAID5 三种轮转（右异步、左异步、左同步）；RAID6 三种 DDF 轮转（Q 按列号编号）；RAID1E 相邻镜像；以次级条带组合的 RAID1 子卷（RAID10）；成员等大的串联（CONCAT） |
| 卷大小 | 元数据记录的卷大小。每盘使用量由条带数计算，与卷大小相差超过每盘 1 MiB 时改为卷大小按数据盘均分 | 配置记录的卷大小；有次级级别时，若该字段恰为一个子卷的大小，则按全部子卷计算 |
| 只列出、不组装 | 容器使用不支持的元数据属性（SSD 缓存加速、Clone-and-Go 等）；卷处于常规迁移（改级别、扩容、改成员数或条带）或状态变更迁移；其他级别与成员数 | 虚拟盘正在重构（morphing）；RAID3、RAID5E / 5EE、JBOD、RAID1E 偏移镜像、RAID1 以外的次级组合（如 RAID50 / RAID60）；成员大小不同的串联；同一虚拟盘的子卷记录在级别、条带或大小上不一致 |

阵列卡片的「元数据版本」显示 `imsm <版本>` 或 `ddf <修订号>`。卷名取自元数据；整卷文件系统标为 `<文件系统> (imsm/<卷名>)` 或 `<文件系统> (ddf/<虚拟盘名>)`。

## 成员状态与降级

规则与 md 相同（见 [Linux md RAID](MDRAID.md#降级组装)）：

- 某块盘上的元数据比权威副本落后超过一次更新时为「陈旧」，不读取。
- 元数据记为故障、缺失或正在重建的盘，其槽位自动按校验或剩余镜像重建，阵列显示「已降级重组」；正在重建的盘若已加载，标为「重建中」，不读取。
- 元数据仍视为在线、但没有加载或已陈旧的盘：阵列停在「缺 N 块，可降级重组」，在 RAID 卡片中点「降级重组」确认，或在 CLI 中用 `raid detect --degraded-sets <set_uuid>`。
- 元数据表明校验可能与数据不符时——IMSM 卷未正常关闭、从未初始化或仍在初始化，DDF 虚拟盘标为不一致或未完成初始化——即使缺盘已被记录，按校验重建也需要确认，诊断会说明原因；镜像级别不受影响。
- 同一块盘加载两次（序列号或引用号相同且元数据完全相同）只读一份，另一份标为「重复加载」；不同的盘声明同一条磁盘记录时不组装。
- 备用盘列为「备用」，IMSM 日志盘列为「日志盘」。

## IMSM 成员识别

IMSM 不在盘上记录"自己是哪一块盘"，磁盘表只保存每块成员盘的序列号，而序列号由硬盘报告，不在盘面数据中。检材按以下顺序匹配磁盘记录：

1. Windows 物理磁盘检材在只读打开时，通过 `IOCTL_STORAGE_QUERY_PROPERTY` / `StorageDeviceProperty` 的 `SerialNumberOffset` 读取设备报告的序列号，去掉两端空白；E01 使用采集头记录的序列号。两者按固件的规则规整：去掉空白、控制字符和非 ASCII 字符，`:` 换成 `;`，只保留最后 16 个字符。ATA / ATAPI / SATA 设备的原始字段长度为偶数字节时，同时核对逐字交换字节的解释（交换前保留填充空格），只有两种解释合计匹配唯一一条记录时才确定成员；不会凭总线类型直接认定设备使用哪种字节顺序。序列号没有匹配或匹配多条记录时给出诊断，继续按大小匹配。
2. 镜像大小与且只与一条磁盘记录的磁盘大小相同。

仍无法匹配的检材只在不影响读取结果时代替成员：卷为 RAID1，并且所有未被匹配的磁盘记录都是该卷的在线槽位（没有故障、重建中、备用盘或只属于其他卷的盘）时，未匹配的镜像按加载顺序填入这些槽位，诊断会注明。

其他情况——例如没有序列号的 RAW 镜像组成的 RAID0、RAID5、RAID10——不组装：成员标为「未匹配」，阵列显示「成员顺序未知」，诊断给出手动重组所需的级别与布局、块大小、数据偏移和成员数，在镜像信息页的「手动重组」中按列序选择成员盘即可。物理磁盘序列号查询失败、字段缺失或损坏时返回无序列号，不从设备路径、型号或磁盘内容推造；Linux / macOS 等其他平台目前不读取物理磁盘序列号，同样返回无序列号。

## 与其他流程的关系

- 只探测整盘块设备检材；文件夹、归档、AD1 等逻辑证据和仅索引会话不参与，已作为整盘 md 成员的检材跳过。
- 带有可用 IMSM / DDF 元数据的检材不交给无元数据启发式；元数据损坏的检材仍可参与启发式推定。
- 成员盘本身也能看到卷的分区（RAID1 镜像，或条带卷的第一块盘）。从成员盘读到的 LVM PV 与组装卷上的是同一个 PV，不重复计入卷组，卷上的 LVM 按组装卷识别。
- 组装后的识别与 md 相同：分区表、整卷文件系统、LVM PV、LUKS 等；未识别出结构的卷也会注册，可做十六进制查看、文件恢复和导出。
- 成员检材的坏扇区（容错后端补零的字节）与 md 阵列一样处理：冗余级别改读其他副本或按校验重建，其余字节按阵列偏移记入组装卷的坏区报告，见 [Linux md RAID](MDRAID.md)。

## 限制

- DDF 只读 512 字节扇区的成员盘；锚点不在最后一个扇区的磁盘（部分 LSI / PERC 固件把元数据放在盘尾之前的保留区）不识别。
- 写意图位图、PPL、IMSM 与 DDF 的坏块日志不回放，标为坏块的扇区仍按成员内容读取。
- Intel Smart Response（SSD 缓存加速）卷与 DDF 厂商专有配置记录不处理；迁移和重构中的卷只列出成员与诊断。

## 实现入口与验证

- `core/evidence/raid/imsm.rs`：MPB 读取、校验和、4096 字节扇区换算、序列号规整与卷标识（签名、原始 family number、卷序号和卷名的 SHA-1，与 mdadm 的推导相同）。
- `core/evidence/raid/ddf.rs`：锚点、主备头、各结构的读取与 CRC。
- `core/evidence/raid/imsm_identity.rs`：按序列号与磁盘大小把检材对应到磁盘记录，识别重复加载与冲突。
- `core/evidence/physical_disk.rs` 与 `physical_disk/descriptor.rs`：Windows 设备描述符查询、返回长度与字符串边界检查，以及设备序列号和 ATA 字节顺序解释；`DiskImage.physical_drive_serial` 保留设备报告值，E01 采集信息单独保留。
- `core/evidence/raid/imsm_array.rs`、`ddf_array.rs`：权威副本、槽位与成员状态；`ddf_geometry.rs`：DDF 级别到 md 级别与布局的映射、子卷记录一致性；`firmware.rs`：整盘探测、与 md 一致的降级规则、读取器构建与按元数据卷大小截取。
- 前端 `src/features/raid/model/stackView.ts` 为「未匹配」成员与「成员顺序未知」状态提供显示文字。

物理磁盘身份测试使用合成 Windows 设备描述符，覆盖缺失 / 越界的序列号偏移、截短与未终止字符串、填充空白、无效字节和 ATA 字节交换。固件 RAID 回归覆盖按设备序列号把乱序加载的同容量 RAID5 成员放回槽位、逐字节核对卷内容，以及两种字节顺序匹配不同记录时拒绝组装；不依赖真实物理磁盘。

测试全部使用代码生成的合成元数据与成员盘。解码测试覆盖两种格式的字段、校验和与 CRC 损坏拒收、IMSM 多扇区 MPB 与 4096 字节扇区元数据、DDF 主备副本选择、损坏副本回退和与锚点不一致的副本。端到端测试逐字节核对读回结果：IMSM 的 RAID0 / 1 / 5 / 10、同盘两卷、按序列号与按大小匹配、无法匹配的条带卷、可互换的镜像、故障 / 缺失 / 重建中 / 陈旧成员、迁移中的卷、损坏的 MPB 以及成员盘上 PV 的去重；DDF 的 RAID0 / 1 / 4 / 5（全部轮转）/ 6（三种 DDF 轮转下双盘故障重建）/ RAID1E / RAID10（次级级别）/ 串联、各盘不同的起始扇区、缺盘确认、陈旧与重复加载、配置记录 CRC 损坏、不支持的级别、重构中与未完成初始化的校验。仓库内没有真实 IMSM / DDF 检材，也没有与 mdadm 或控制器逐字节对照的外部样本测试；变更后运行 `just test raid`。
