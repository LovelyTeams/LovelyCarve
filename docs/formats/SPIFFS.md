# SPIFFS

LovelyCarve 使用纯 Rust 只读打开 SPIFFS 的逻辑闪存镜像或分区。可浏览文件、预览、按范围读取、哈希和导出。

## 可读布局

- 支持 16 位对象 ID、页索引和 span 索引的大小端布局。识别常量签名和包含卷块数的签名，打开时校验每个查找块的签名，允许一个擦除后尚未写入签名的块。无签名镜像需要有足够的对照页才能唯一确认几何。
- 已验证 256 字节页 / 4 KiB 块的 ESP32 布局，以及 512 字节页 / 8 KiB 块的大端对齐布局。读取原始文件头并对照对象索引和数据页推断索引表偏移，可适配不同的名称长度、用户元数据长度和对齐方式。
- SPIFFS 用扁平对象名称存储路径。`/logs/event.bin` 在根目录显示为 `%2Flogs%2Fevent.bin`。斜线、反斜线、百分号、控制字符和非 UTF-8 字节均按 `%HH` 显示，文件查找区分大小写。
- 通过分配表、索引页和数据页中的对象 ID 与 span 确认页归属。索引缺损的文件仍可查看元数据，预览、哈希和导出会报告读取错误。SPIFFS 数据页没有内容校验和。

## 边界与验证

- 无签名且为空、占用太少或几何含糊的镜像可能无法自动识别。需要厂商分区表才能定位的整片闪存应先提取对应分区。当前不恢复已删除对象，不解释应用自定义元数据和时间戳。
- `just test-vendor spiffs-reader` 和 `just clippy-spiffs` 验证独立读取器。CLI 端到端测试覆盖裸卷、MBR、大小端、跨索引页范围、哈希和导出。样本来自乐鑫官方 ESP-IDF 生成器和 SPIFFS 上游实现。原生写入的样本还覆盖追加、重命名和删除后的页面状态。来源和哈希见[读取器来源记录](../../src-tauri/vendor/spiffs-reader/ORIGIN.md)。
