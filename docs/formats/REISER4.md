# Reiser4

LovelyCarve 通过 `reiser4-reader` 只读打开 4 KiB、Format40 4.0.0–4.0.2 的干净单设备卷。裸卷和分区都使用 `reiser4` 类型。[ReiserFS 3.5 / 3.6](REISERFS.md) 由独立读取器处理。

| 能力 | 范围 |
| --- | --- |
| 卷与树 | 主超级块、格式超级块、状态和日志头尾，短键和长键，node40 和带 CRC32C 的 node41，按对象键区间走树 |
| 目录与元数据 | cde40 聚集目录项、内联短名和存储在条目中的长名，硬链接、符号链接、文件模式、UTC 秒级修改／访问／状态变更时间 |
| 内容 | plain40 尾部打包、extent40 已分配区段和显式空洞，有界范围读、流式读取、哈希和导出 |
| 校验 | 对所访问的节点检查级别、分隔键、排序和范围，对数据区段检查分配位图及其 Adler-32、卷边界、逻辑大小和物理重叠 |

有待回放或修复的卷会报错。当前不支持 ctail40 压缩簇、文件加密、Reiser5 多设备、ACL 或扩展属性的解码，也不恢复删除记录。目录名通过现有的 UTF-8 路径接口提供，无法表示的名称会报错。一次对象查询最多访问 131072 个树页并载入 64 MiB item 数据。大文件通过 extent 映射读取，空洞只在磁盘结构明确记录时补零。

两份原生 4.0.2 卷通过 `fsck.reiser4 --check`。上游工具列举目录并按字节导出普通文件及含空洞的文件。`just test-vendor reiser4-reader` 检查两个布局、跨叶和跨洞读取、硬链接 inode、重新打开后的节点定位，以及截断、日志未同步和 CRC 错误。`just test-cli` 验证裸卷与 MBR、路径和节点 ID、符号链接、哈希和导出。[样本来源](../../src-tauri/vendor/reiser4-reader/ORIGIN.md)
