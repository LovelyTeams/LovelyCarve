# Linux md RAID

Linux 软件 RAID（md / mdadm）由纯 Rust 代码识别与重组，结果注册为只读的合成检材（`assembled://…`），之后的浏览、哈希、导出、索引与普通磁盘相同。条带、校验与副本的位置按 Linux md 各级别对磁盘格式的定义实现；同一套读取器也用于无元数据阵列的启发式重组和手动重组。实现入口见文末，整体流程见 [架构说明](../ARCHITECTURE.md)，与 md 叠加的 LVM 见 [LVM2](LVM.md)。

## 能力矩阵

| 项目 | LovelyCarve 实现与边界 |
| --- | --- |
| 超级块版本 | 1.2（距起点 4 KiB）、1.1（起点）、1.0（距末尾 8–12 KiB，4 KiB 对齐）、0.90（末尾 64 KiB 对齐的最后一个 64 KiB 区，大端与小端主机写入的均可读） |
| 超级块校验 | 1.x 按 `max_dev` 覆盖的范围计算校验和，并核对记录的 `super_offset` 与实际位置一致；0.90 按 16 位折叠后的校验和比较。校验失败的超级块列入诊断，不参与组装 |
| 成员来源 | 整盘、分区（扩展分区、LVM PV、LUKS / BitLocker / FileVault 等容器除外）与完整的 LVM 线性 LV。分区恰好结束在磁盘末尾时，末尾超级块对整盘和分区都可见，归属最内层的分区 |
| 当前成员 | 以事件计数最高的超级块为准：落后 1 次的成员照常读取，角色取自最新角色表；落后更多的成员为「陈旧」，不读取；仍在重建（`recovery_offset`）或替换其他成员的设备为「重建中」，不读取；备用、故障与日志设备不占槽位 |
| 重复与冲突 | 同一设备加载两次（设备号、事件计数与设备 UUID 相同）只读一份，另一份标为「重复加载」；两台不同设备声明同一槽位时不组装并给出诊断 |
| linear | 按槽位串联各盘数据区；chunk 非 0 时各盘按整 chunk 取整 |
| RAID0 | 等大成员为单区条带；成员大小不同时按 md 的分区规则在较大成员上继续条带。第二区之后的位置由元数据记录的布局（1.x 的 RAID0 布局特性或 0.90 的 layout）决定，未记录时按原始布局读取并给出诊断——Linux 3.14–5.3 创建的此类阵列用的是另一种布局 |
| RAID1 | 读最低槽位的在线镜像；该镜像读取失败（截断、不可读）时改读其他镜像，每个镜像首次改读记一条警告；该镜像中成员检材补零的字节改从其他镜像读取 |
| RAID4 / RAID5 | RAID5 布局 0–5：左/右 × 异步/同步，以及首盘 / 末盘固定校验；RAID4 校验在末盘。缺一列时由 P 校验重建；成员检材补零的字节按缺列处理，同样由校验重建 |
| RAID6 | 布局 0–5、DDF 轮转 8–10 与「Q 固定末盘」16–20。Q 为 GF(2^8)（多项式 0x11d、生成元 2）上的校验；md 布局从 Q 之后的列开始给数据列编号，DDF 布局按列号编号。缺一列数据用 P 重建，P 也缺失时用 Q；缺两列数据按双擦除方程求解。补零的字节计入缺失列：同一位置缺失与补零合计不超过两列时仍可重建 |
| RAID10 | near / far / offset 副本及其组合，含 layout 第 17–18 位选择的三种 far set 分组；每个数据块读取第一份在线副本，读取失败时改读其他副本，补零的字节改读其他副本 |
| 阵列大小 | RAID1/4/5/6/10 用超级块记录的每盘使用大小，条带级别按整 chunk 取整；RAID0 与 linear 用各盘数据区。末尾不足一个 chunk 的部分不可寻址 |
| 组装后识别 | 与普通检材相同：分区表、整卷文件系统、LVM PV、LUKS 等。阵列直接承载一个文件系统时，该分区标为 `<文件系统> (md · <阵列名>)`；未识别出任何结构的阵列也会注册，可做十六进制查看、文件恢复和导出 |
| md 上的 LVM | md 阵列上的 PV 与其他检材上的 PV 一起组成卷组。完整且未用作 md 成员的线性 LV（单 PV 及群晖 SHR 等跨 PV 卷）均另行注册为「逻辑卷 <卷组>/<卷>」镜像 |
| 读取完整性 | 阵列范围内任何成员短读、越过数据区或缺少重建所需的列都会让读取失败，不以零字节补齐 |
| 读故障审计 | 成员检材的容错后端（E01、VMDK 等）把坏扇区补零时，冗余级别先改读其他副本或按校验重建；没有可信来源的字节保持为零，按阵列偏移记入重组镜像的坏区报告，哈希、RAW 导出与文件导出的 `bad_regions`、`synthetic_bytes`、`read_faults_detected` 和严格读取策略与普通检材一致。重建不拿补零字节参与运算；成员检材自己的坏区报告仍保留原记录 |

## 降级组装

组装所需成员缺失时，按 md 自身的记录决定是否自动降级：

- 最新超级块已把缺失的槽位记为空（成员被 md 标为故障后移除），或该槽位的设备在本次检材中仍处于重建状态：md 当时就以降级状态运行，阵列自动按校验或剩余镜像组装，状态显示「已降级重组」。
- 元数据仍登记、但没有加载或已陈旧的成员：阵列停在「缺 N 块，可降级重组」。加载其余成员盘后自动完整组装；确认缺盘无法获得时，在镜像信息页 RAID 卡片中点「降级重组」，或在 CLI 中用 `raid detect --degraded-sets <set_uuid>`。选择只在当前案件会话内有效。
- 缺失超过级别的冗余（RAID0、linear 缺任一成员，RAID4/5 缺两列，RAID6 缺三列，RAID10 某数据块的全部副本）时只显示「成员不全」。

阵列未正常停止（超级块记录了未完成的同步位置）且需要降级重建时，诊断会提示：崩溃前后写入的条带校验可能不一致，重建出的数据需要结合文件系统校验判断。

## 手动重组

镜像信息页的「手动重组」按列序选择成员盘并指定几何：级别（linear、RAID0/1/4/5/6/10）、RAID5/6 校验布局、RAID10 副本布局与副本数、块大小和每盘数据偏移。没有镜像的成员盘用「缺盘列」占位；已加载但内容不可信的列可标为不读取，按校验或镜像重建，数量不超过该级别的冗余。界面中的条带示意由同一套布局规则生成，可在预览前核对。CLI 对应 `raid assemble --params <JSON>`，空字符串的成员 ID 表示缺盘列。

## 限制

- 正在 reshape（扩容、改级别、改块大小）的阵列新旧布局混合，只列出成员与诊断，不组装。
- 写日志设备、PPL 与写意图位图不回放；md 坏块日志不应用，标为坏块的扇区仍按成员内容读取。
- Intel IMSM 与 SNIA DDF 容器（mdadm 的外部元数据）由固件 RAID 流程按各自的元数据组装，读取器与降级规则相同，见 [固件 RAID](FIRMWARE_RAID.md)。其他硬件 RAID 控制器的私有元数据、Windows 动态磁盘、ZFS 与 Btrfs 的多设备冗余不走此流程；无元数据的等大成员盘由启发式按 RAID0 / RAID5 推定（见 [架构说明](../ARCHITECTURE.md)）。
- LVM 非线性段（striped、mirror、raid、thin 等）仍只保留元数据，见 [LVM2](LVM.md)。

## 实现入口与验证

- `core/evidence/raid/mdadm_super.rs`：四种超级块的解码、校验和与位置核对。
- `core/evidence/raid/md_array.rs`：当前成员、槽位、降级与诊断规则；`detect.rs`：候选设备枚举、最内层超级块归属和整体流程；`lvm_stack.rs`：md 上的 PV 与跨 PV 逻辑卷。
- `core/evidence/raid/source/`：各级别读取器（`striped`、`mirror`、`raid10`、`linear`）、校验布局（`parity_layout`）、GF(2^8) 运算（`gf256`）、把缺失与补零的列一起计入的校验重建（`rebuild`）、成员补零区间的传递与按副本修补（`traced`）与按级别构建读取器（`build`）。
- 前端条带示意 `src/features/raid/model/stripeLayout.ts` 与后端使用同一套布局规则，两侧测试核对相同的布局表。

测试全部使用代码生成的合成成员：各 RAID5/6 布局的位置与 md 布局表逐行比对，GF(2^8) 运算核对已知幂值与逆元；读取器测试覆盖全部布局在每一种单列、双列缺失组合下逐字节还原、截断成员与越界读取报错；读故障测试让成员按偏移补零（含截断的 VMDK 成员），逐字节对照期望——某列在该位置缺失或补零、且缺失与补零的列数超过冗余时才上报——覆盖全部条带布局的完整与降级阵列、RAID1、RAID10、linear 与跨 PV 逻辑卷，并经 `DiskImage` 核对哈希与导出读取到的坏区报告；端到端测试覆盖 1.2 RAID5、1.0 RAID6 降级、0.90 RAID1、RAID10、linear、陈旧与重建中成员、损坏的超级块、分区与整盘共享末尾超级块，以及两组 md 上跨 PV 的逻辑卷。仓库内没有真实 md 检材，也没有与 Linux 内核逐字节对照的外部样本测试；变更后运行 `just test raid`。
