# Encrypted image integration fixtures

Generated by `scripts/make-encrypted-fixtures.py` using Python cryptography / OpenSSL,
independently of the production Rust readers. Public test password: `lovelycarve-test`.
VeraCrypt PIM: **1**; `hidden.hc` uses the hidden header at 65536 bytes (the unlock finds it without being told).
LUKS1 uses PBKDF2-SHA256; LUKS2 uses Argon2id and 4096-byte encryption sectors.
`veracrypt-keyfile.hc` also needs the keyfile `veracrypt-keyfile.bin`; `veracrypt-system.img` is a disk whose
MBR partition 1 (at 64 KiB) is system-encrypted, with the header in sector 62 and
SHA-256 at the pre-boot count for PIM 1 (2048 iterations).
All encrypted images decrypt to `plain.img` (FAT12 with `HELLO.TXT`). See `sha256.json`.
The deliberately tiny KDF costs are for regression tests only.

These are synthetic format fixtures, not evidence acquired from a real system.
The public cryptsetup VeraCrypt corpus is tested separately and is not redistributed here.

Verification: `just test encrypted_image_tests`, `just test-cli`; standalone reader
suites: `just test-luks --release`, `just test-veracrypt`. The VeraCrypt reader also
carries its own independent corpus (`src-tauri/vendor/veracrypt/tests/data`).
Optional real VeraCrypt oracle inputs (`VC_ORACLE`, `VC_HIDDEN_ORACLE` and the
cipher variants) are listed in `docs/formats/VERACRYPT.md`. Unset oracle paths
cause those tests to return early; a green aggregate alone does not prove oracle
execution.
