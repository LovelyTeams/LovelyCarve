# forensic-board 配合 LovelyCarve CLI 解题

本流程用于用户要求通过 forensic-board MCP 管理取证题目、答案与线索的任务。MCP 管题单和共享记录，LovelyCarve CLI 只读访问检材并产生可复核结果。普通 CLI 查询无需建立看板；仅要求导入题目时，完成导入与回读就结束，不开始调查。

## 接入与竞赛范围

使用宿主实际连接的 forensic-board 工具名称及前缀，先查看其工具参数契约。下面的名称指 MCP 操作，不是 CLI 子命令。复用现有连接，不按安装目录猜端点、不另建客户端、不直接修改看板数据库。认证信息由宿主配置，不能写进技能、聊天或版本库。

先 `list_competitions` 精确核对竞赛完整名称，开始或恢复时读取 `list_questions` 和相关 `list_clues`。沿用用户或上下文已明确的目标；相似名称不能靠模糊匹配随便选。新题未指定竞赛名时，使用用户时区当日的 `YYYY-MM-DD`，同名则复用；不能从题目年份推断日期。已有竞赛目标仍有歧义时先澄清，可以先只读查看列表。

此流程直接使用 MCP，不依赖 LovelySkills 专用的 `dfir_dashboard`、`dfir_route`、`dfir_question_timer` 或自动回读钩子。这些能力未实际提供时不能声称已启动计时、自动校验或暂停后续工具。

## 登记题单

保留原题号、完整题干、题型及选项原序。`category` 优先沿用用户分组，否则按主要检材或任务分类，例如计算机取证、服务器取证、手机取证；信息不足用“待分类”，不为分类扫描检材。先核对已有题，新增才调用 `import_questions`：

```json
{"competition":"<竞赛完整名称>","questions":[{"number":"Server-20","category":"服务器取证","type":"填空","stem":"<用户提供的完整题干>"}]}
```

选择题显式填写 `type: "单选"` 或 `"多选"`；`options` 是按 A、B、C 顺序的选项内容字符串数组，不加字母前缀，不排序或补造选项。导入后用 `list_questions` 回读核对题号、类别、完整题干、题型、选项和数字 ID。返回的 `题型` 为中文标签，`选项` 为字母到内容的映射，以实际服务结果为准。

题号字符串与返回的数字 `id` 不同，后者才是 `question_id`。重复导入不能当作编辑已有题；题型或选项有误时使用看板实际支持的编辑能力，无法编辑则报告缺口。超时先回读，只补确认缺失的题。仅导入任务到此报告竞赛、实际新增/重复数量、分类及缺失项后结束，不打开检材或登记分析线索。

## 读题、选证与最小验证

每题先 `get_question(question_id)` 读取最新原题及全部候选，再 `list_clues` 查相关线索。明确要回答的对象、范围、单位、格式、大小写、时间角色与时区，区分“保存的密码”和“成功登录”、“已安装版本”和“实际运行版本”、“最后一次”和“最早一次”。已有候选是调查入口，不能直接当作正确答案或独立证据。

按题目依赖排序：例如密钥 → 解锁 → 读取配置。优先处理能解除多题阻断的前置问题；同一检材或数据库集中读取并复用结果。主线逐题进行，不为每题重建会话、重复装配、重复解密或默认导出原文件。先按 [案件与会话](workflows.md#sessions-and-cases) 建案/恢复、加载检材并核验所需索引，再读取证据。恢复时核对当前 CLI 会话、检材和卷；看板中有路径不代表源文件当前可读。

可信解析记录或原始记录直接给出所求值，检材、对象和账号对应明确，格式符合题意且没有未解决冲突时，证据已足够，立即提交。只有会改变答案的具体缺口才补查，例如解析异常、字段缺失、对象关联不明、来源冲突或“最早/全部”的覆盖不足。用户明确要求复核时按其范围执行。解析结果和底层文件属于同源，自查不算独立印证；未亲自读取的底层文件不得列为已核验。

每次 CLI 或其他证据工具返回后，对照授权题单检查是否已得到答案，包括顺带回答的其他题。先完成这些答案的提交和回读，再继续主线；不等整组题完成。多个检材联合题分别记录各侧事实及关联依据，单侧命中不能写成联合验证。分页、文本分段、索引覆盖、解码错误和读故障按 [完整性规则](../SKILL.md#check-the-outcome) 检查，单页未命中不能证明不存在。

## 答案提交闭环

按真实数字 ID 逐题串行执行：`get_question` 查重 → `submit_answers`（修正已有候选用 `update_answer`）→ `get_question` 回读。长时间分析或切题后提交前刷新原题。一个输出回答多题时，依次完成各题闭环再继续调查；歧义题保留未答，不能拖住其他可靠答案。

```json
{"question_id":123,"answers":[{"answer":"<符合题意的答案>","reason":"<实际观察、推导及验证边界>","evidence":["<源检材完整路径；卷及证据内路径；表/主键、字段、行号或偏移等实际定位>"],"confidence":0.8}],"agent":"<本会话实际标识>"}
```

- `answer`、`reason` 为非空字符串，卡号、UID、带前导零的数值也用字符串；`evidence` 为可复核来源字符串数组。`confidence` 为 0～1 数字或省略，不能用高置信度代替证据。
- 单选 `answer` 只填一个大写字母，如 `B`；多选去重、按字母升序组成一条候选，如 `ACD`，不能拆为三条。选项文字与推理放 `reason`。以最新题型与选项映射为准；选项缺失先核对原题，旧服务无题型时保留原文本语义，不猜字母。
- 同一候选已存在且依据一致时不重复提交。修正自己的候选前，先确认 `answer_id` 所属题目；`update_answer` 的 `evidence` 整体替换，保留仍有效的来源。有不同依据的争议候选分别保留，不静默覆盖或删除他人记录。
- 回读核对所属题目、真实 `answer_id`、答案、理由与证据。写入返回成功仍需核对保存内容；有候选、已回读、人工确认正确分别报告，不能混为“全部答对”。

来源应能在会话重启后复现：记录源镜像/备份/文件夹完整路径、所选卷及证据内路径、实际字段或记录定位。可附当时 `imageId`、`volumeKey`、返回的节点 ID、CLI 命令/查询条件和产物路径，但进程内 ID 不能单独替代源定位。数据库写明表、主键和查询，日志写行号/事件 ID，字节写偏移基准（容器、客体磁盘或文件）及长度，插件结果写实际插件、运行与记录定位；时间保留原值和时区依据。没有的字段不编造。

题目没有可靠答案时保留未答，不提交空串、`skipped`、错误信息或阻断原因充当候选。看板保存候选不等于人工确认最终答案，也不等于向比赛平台交卷；平台提交按用户明确授权执行。

## 线索发现即保存

密码、密钥、账号、Token、URL、主机角色、人物关系、解题依赖及跨题有用的失败方法，发现后及时 `submit_clues`，无需等某题完成或强行关联题号。已有可靠答案先提交并回读，再补充线索。提交前用 `list_clues` 按类别/关键词查重，保存后再次读取核对内容、说明、来源与返回 ID。

```json
{"competition":"<竞赛完整名称>","clues":[{"content":"<实际发现的原文或可观察事实>","category":"<线索类别>","description":"<用途、关联线索 ID、观察状态及待验证点>","source":"<源检材；卷/证据内路径；字段、表与主键、行号或偏移>"}],"agent":"<本会话实际标识>"}
```

类别是自由文本；以下为约定，不是服务枚举：

| 类别 | 应记录的内容与边界 |
| --- | --- |
| 检材归属 | 完整源路径/检材标识 → 对象及具体关系 → 依据；说明原始还是派生，派生文件写清源文件及导出位置。清单标注、用户说明、内容核验分开写，导出来源不能自动证明持有人或使用人。 |
| 账号密码 / 解密材料 | 原始值、对应账号/应用/卷、适用范围、发现字段及验证状态。已发现且允许题内保存的密码、密钥、Token 保留原文；保存、解锁成功和历史使用是不同事实。私钥只记录已有定位，不复制私钥内容。 |
| 人物关系 | 双方实际姓名或标识、具体关系与方向、适用时间、可复核记录；陈述注明说话方，推断保留缺口。昵称相同、一次聊天或转账不单独证明真实身份或更强关系，关系不自动传递。 |
| 检材连接 | 已知主机/IP、实际端口、账号、认证方式及允许保存的密码原文；引用检材归属线索，区分用户提供、可达、认证成功和目标身份匹配。候选地址标待核实，未知信息不猜默认值；派生客机重置的密码不当作历史密码。 |
| 解题依赖 / 排除记录 | 受影响题目、已尝试方法、真实错误、已检查范围和恢复条件；“此方法失败”不能写成“证据不存在”。 |

首次读取本次授权检材清单后，及时登记已知的源文件对应与依据，供后续选证复用。LovelyCarve 的案件目录、源检材路径、`imageId`、卷及节点分别标明，不套用 GES 的 cid/eid/route，也不把 CLI ID 当作看板 ID。分卷、伴随文件、RAID 成员与派生解锁视图按实际来源关系记录；同名文件或克隆 UUID 不能自行合并成一台设备。

解密、登录或切换检材前刷新相关线索并核对目标。新发现与旧记录冲突时引用旧线索 ID，追加新依据和观察时间，不静默覆盖。共享线索引用真实发现来源；同一记录被多人转述不构成独立印证。不为补全人物网或归属表扩大到无关检材。

凭据只保存在当前授权竞赛的看板记录；不要在技能源码、Git、安装包、额外本地账本或进度消息中复制。使用 CLI 的密码文件/stdin 接口时按需创建临时输入，避免在命令参数、请求日志中回显，使用后按原有凭据处理规则清理。保存连接信息不自动授权登录或试用凭据。

## 失败、受阻与恢复

提交超时、断连或回读失败时保留真实返回 ID，先 `get_question` / `list_clues` 检查服务实际保存内容，再仅补缺失项，不能盲目重放整批。明确校验拒绝时按实际错误修正参数；不要用拆批绕过校验。未核对成功前报告“提交结果尚未核验”，暂停新的调查及无关写入，优先补齐保存闭环。连接不可用则报告待提交内容与连接缺口，不另建本地答案/线索白板，不声称已经共享。

证据或 CLI 受阻与看板写入未决分开处理：前者说明真实错误、受影响题目、既有产物及可检查的恢复条件，继续不依赖此阻断的授权题目；后者先完成回读核对。后台任务保留真实任务 ID，在原会话检查状态，超时不代表任务已停止，不能重复发起装配或解密。

默认单题约 15 分钟作为分析检查点，按用户约定调整；遇到明确阻断可提前切题。到点说明已得证据、未决原因和下一步，保留未答，不为赶时提交猜测。只有实际可用的计时能力才报告计时；恢复不虚构重置旧预算，不需要创建本地题库或计时账本。提交、切题、受阻及后台等待时简短报告已保存答案和待核实项，进度基于最新题单及实际候选。

恢复从看板最新题单、候选和线索开始；把上下文中已有证据支持但尚未保存的答案先补交并回读，再继续读取检材。大型导出、数据库副本和解析产物保存在工作目录，看板保留其来源及可复现定位。
